Comparing Scenario B (Delayed ACK) with Scenario C (Adjusted Timeout) reveals the core lesson: increasing the timeout prevents the unnecessary retransmission — but only because the ACK still arrives before the longer timeout expires. A longer timeout is not a universal fix; when a frame or ACK is actually lost, a longer timeout delays recovery. The correct solution is to tune the timeout to match realistic round-trip times.

Protocol Theory

Understanding the mechanics behind Stop-and-Wait ARQ.

🔄

ARQ — Automatic Repeat reQuest

ARQ is an error-control method for data transmission that uses acknowledgements and timeouts to ensure reliable delivery. The sender waits for confirmation before moving on.

⏸️

Stop-and-Wait Operation

The simplest ARQ protocol: send one frame, wait for its ACK, then send the next. At most one unacknowledged frame exists at any time, making it easy to reason about but potentially slow.

✅

Acknowledgements (ACKs)

The receiver sends an ACK after accepting a data frame. In this model, ACK 0 acknowledges data frame 0 and ACK 1 acknowledges data frame 1. The sender must wait for the matching ACK before advancing.

⏰

Sender Timeout

To handle lost or excessively delayed ACKs, the sender starts a timer when it transmits. If the timer expires before the ACK arrives, the sender retransmits.

🔁

Retransmission

A retransmission resends the same frame with the same sequence number and payload. It is not a new frame — it is a second (or third…) copy of the same logical message.

0️⃣1️⃣

Alternating Sequence Numbers

Only two sequence numbers are needed: 0 and 1. They alternate with each successfully delivered frame. This lets the receiver tell whether an arriving frame is new or a duplicate.

🚫

Duplicate Suppression

When a retransmitted frame arrives, the receiver compares its sequence number against the expected value. If they match, it's a new frame. If not, it's a duplicate — acknowledged but not delivered.

📐

ACK Arrival Time Formula

ACK arrival = data travel + ACK delay + ACK travel
Example: 100 + 900 + 100 = 1,100 ms

If this is greater than the sender timeout, a retransmission will occur.

⚠️ Model Assumptions

  • Fixed propagation delays (no jitter or random variation).
  • No packet loss or corruption — only delay is modelled.
  • No frame serialisation time or processing overhead.
  • No packet reordering — frames arrive in transmission order.
  • The receiver generates a separate delayed ACK for each received copy of a frame.
  • Tie-breaking: when an ACK arrival and a timeout coincide at the same simulation time, the ACK is processed first, cancelling the timeout.

Exam-Style Question & Worked Answer

A complete worked example based on the assignment scenario.

Question

A sender uses Stop-and-Wait ARQ. Data travel time is 100 ms, receiver ACK delay is 900 ms, ACK travel time is 100 ms, and sender timeout is 600 ms. There is one unique data frame to deliver. No frames are lost or corrupted.

(a) When does retransmission occur?
(b) How does the receiver handle the retransmitted frame?
(c) When does the sender complete the transfer?
(d) How many duplicate frames arrive at the receiver?

Worked Answer

1
Original frame transmission (t = 0 ms)
The sender transmits DATA 0 (Message 1, sequence 0, attempt 1) and starts its timer set to 600 ms.
2
Receiver accepts the frame (t = 100 ms)
DATA 0 arrives at the receiver. Sequence 0 matches the expected value, so the payload is delivered to the application. The expected sequence advances to 1. The receiver schedules ACK 0 to be sent after a delay of 900 ms, i.e. at t = 1,000 ms.
3
Sender timeout and retransmission (t = 600 ms)
The sender timer expires. The ACK has not yet arrived (it will be sent at 1,000 ms and arrive at 1,100 ms). The sender retransmits DATA 0 (attempt 2) and restarts its timer.
4
Receiver discards the duplicate (t = 700 ms)
The retransmitted DATA 0 arrives. Sequence 0 does not match the now-expected sequence 1, so it is identified as a duplicate. The payload is not delivered again. A second ACK 0 is scheduled for t = 1,600 ms. The duplicate counter increments to 1.
5
Receiver sends the original ACK (t = 1,000 ms)
The ACK 0 for the original frame is emitted and travels for 100 ms.
6
Transfer complete (t = 1,100 ms)
ACK 0 arrives at the sender. The sender cancels any outstanding timer and marks the transfer complete. All messages have been acknowledged.
7
Extra ACK arrives (t = 1,700 ms)
The ACK generated for the duplicate frame arrives. Since the transfer is already complete, the sender ignores it (it is a stale ACK for a sequence number no longer being tracked).

Project Guide

Installation, architecture, assumptions, and references.

🚀 Quick Start

cd stop-and-wait-arq
pip install -r requirements.txt
python app.py

Then open http://localhost:5000 in your browser.

🏗️ Architecture

Python (Flask) calculates the complete ordered event trace. JavaScript plays back that trace using simulation times, completely decoupled from the protocol logic.

  • simulator.py — event queue, sender, receiver, timers
  • app.py — Flask routes and JSON API
  • animation.js — visual playback of event trace
  • app.js — controls, metrics, log rendering

✅ Run Tests

python tests/test_simulator.py

Tests verify: normal delivery, delayed-ACK retransmission, adjusted timeout, duplicate suppression, and stale-timer safety.
